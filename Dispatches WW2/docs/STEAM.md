# Dispatches WW2 on Steam: achievements and the controller

The game is a web page. A desktop build for Steam wraps it (Electron or similar) and talks to Steam through a small bridge that the wrapper
puts on `window`. The game never needs the bridge: without it, achievements are kept on the machine and the controller is read through the
browser's Gamepad API.

## Files

Both are generated by `node tools/steam.mjs --write` from the game's own lists, and `npm run check-steam` (in `test:fast`) fails when they
are out of date:

| File | From | Use |
| --- | --- | --- |
| `steam/achievements.json` | part 45, `ACHIEVEMENTS` | Enter each achievement in the Steamworks partner site under its `api` name, with the names and descriptions given (English, and the other eight languages where the game has them). The icons named there are still to be made. |
| `steam/input/game_actions_APPID.vdf` | `src/shell-core.js`, `STEAM_INPUT_ACTIONS` | The Steam Input action manifest. Rename it to `game_actions_<app id>.vdf` and place it as the Steamworks documentation for In-Game Actions says, once the app has an id. |

## Achievements

`unlockAchievements(record)` (part 45) runs each time a file is closed. It works the achievements out from the war record, keeps the list in
`localStorage` (`dispatchesWW2_achievements`), and, if the wrapper provides it, calls

```js
window.dispatchesSteam.unlockAchievement(apiName)
```

for every achievement earned so far, not only the new ones, so one missed while Steam was away is passed again the next time. The wrapper
should call `SetAchievement` and `StoreStats` (Steamworks), and ignore names it has already set. The records page on the opening screen lists the
achievements for players without Steam.

No achievement rewards a victory of the Axis. Endings count as endings found, whoever's they are.

## The controller

The game reads the first controller through the Gamepad API (`useInputControls`, `src/shell-core.js`). On the Steam Deck and with Steam Input
turned on, a Steam Input configuration based on the **Gamepad** template is enough: Steam presents the controller as an Xbox pad and the game's
own bindings apply (A press, B back, Start menu, View journal; the player can move them in the menu, under Keys and controller).

A wrapper that uses the Steam Input API instead reads the actions in the manifest and passes each to the game:

```js
window.dispatchesInput.act("press" | "back" | "menu" | "journal" | "menu_up" | "menu_down" | "continue" | "reconsider" | "order_1" … "order_9")
```

`act` returns whether the action did something. The game installs it when it starts.
