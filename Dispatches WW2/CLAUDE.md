# Dispatches WW2 (six commands: OKW, STAVKA, War Cabinet, Comando Supremo, IGHQ, Joint Chiefs)

Dispatches 1940 and Dispatches 1941 joined into one game. This folder began as a copy of Dispatches 1940 (November 2026); 1941's two commands, battles, map, events, dossiers and claims were ported in. Everything below the "Joined game" section is 1940's guide and still holds for the European commands and for the shared screens. The plan for the commands (Britain and the US replacing SHAEF and CINCPAC, the US effort split, the record across theatres) is `docs/COMMANDS.md`; what is ported and what is not yet is `docs/PORT_STATUS.md`.

## Joined game: how the two games live together
- **Rules by command.** `src/rules.ts` is the only rules module App.jsx imports. It forwards each call to `src/logic.ts` (1940's rules) for the European commands or to `src/logic-pacific.ts` (1941's rules, meters renamed) for `PACIFIC_COMMANDS` (`japan`, `alliedPacific`). `selectRules(campaignId)` switches; WW2CommandInner calls it on every render and wherever the command is set. The tables it re-exports (`METER_STRANDS`, `MATERIEL_STRANDS`, `COMMAND_RANKS`, `STRAND_ALIAS`) are `export let` live bindings. A change to a rule must be made in the right file, and a rule meant for all six commands must be made in both until the two are merged.
- **Meters.** Every command has `manpower`, `fuel` (Matériel) and `initiative`. 1941's `readiness` and `pipeline` were renamed in the ported content, battles, JSON nodes, state events and rules; prose that uses the words ("a training pipeline") was left alone. Its arrears flags keep their old names (`arrearsReadiness`, `arrearsPipeline`).
- **Parts from 1941.** `14-campaign-japan`, `15-campaign-alliedpacific` (plus `src/data/alliedPacific.nodes.json`, inlined by `/*@inline-json*/`, so `npm run split` refuses in this game; edit parts and JSON, then `npm run assemble`), `26-battles-pacific` (the nine Pacific battles on 1940's Order of Battle registries), `33-pacific-map` (1941's whole map layer inside the closure `PACIFIC_MAP`: its `MAP_REGIONS`, `MAP_TIMELINE`, `MAP_PLACES`, `ReportMap` and the rest shadow the European ones only there; its geometry is fetched from `assets/maps/pacific-regions.json`). 1941's state events are `PACIFIC_STATE_EVENTS` at the end of `35-events`, shown through the special-dispatch screen by `pacificStateEvent`.
- **The Pacific map's look** follows the European map (sea `#a6bbb5` and land `#cdbc9a` sampled from `assets/maps/*/1942.png`, the European `STATUS_COLORS` at half strength, the contested hatch, serif labels). Keep the two in step when either changes.
- **Audits.** The tools read all six command files. `check-advisor-dates` covers the European commands only (the Pacific advisers are dated by tenure in 1941; see PORT_STATUS). `tools/check-undefined.mjs` (from 1941) catches a name used in one part and declared in none.
- **Storage keys** are `dispatches-ww2-active-<command>` (one war in progress per command), `dispatches-ww2-slot-<1..3>` (named slots), `dispatches-ww2-record` and `dispatchesWW2_*` (settings, crash reports); never reuse a 1940 or 1941 key. The old single `dispatches-ww2-active` is read once and moved into its command's key by `loadSavedRuns` (part 45); the save fixtures in `tests/saves` still use it, which is what proves the move.
- **The app shell** (part `47-app-shell`): `SettingsRows` (opening screen and in-run menu), `InRunMenu`, `WarJournal`, `RecordsByCommand`, `useKeptSetting`, crash reports (`CRASH_CONTEXT`, `keepCrashReport`; `CRASH_REPORT_URL` is null, so nothing is sent) and `useInputControls`. Keyboard and controller act on `data-hotkey` markers: "1"–"9" on numbered choices (briefing orders, the allocation, the menu), "enter" on each screen's continue button, "r" on Reconsider an Earlier Decision. A new screen's main button should carry `data-hotkey="enter"`. The floating ☰ and ⚙ buttons are labelled "Show the war journal" and "Settings and menu" so the test bots' SKIP pattern passes them over. `tests/saves-slots.test.mjs` covers the saves, slots, journal and keys.
- **The British and American commands** (`british`, `american`; part `16-commands-britain-us`) replace SHAEF and CINCPAC, whose campaigns stay as `sourceOnly` (not offered; the select screen and the "every command" objective skip them). A composite campaign has `tracks`; its `resolveNode` routes each id to its source file (`compositeSourceOf`); `compositeNext` (called from `proceed()` in 50-app) steps through the tracks in date order and passes the other command's reports by the record, keeping each track's place in the flag `trk_<key>`. Report screens get `campaignView(campaign, position)` (the source file's id, so every report-level table works unchanged); maps get `mapHistory`. Ownership is `BRITISH_REPORTS` / `AMERICAN_FROM_ALLIED` / `BOTH_REPORTS`; part `29-composite-tables` builds the two commands' atlas, notes, forks, modes and quotations from the source files' rows. Audits that check report-level data (events, map orders, conditions, staff's reading, orphans) skip campaigns with `tracks`: that data is checked under the source files. Plan and allocation: docs/COMMANDS.md.
- **The American allocation of effort** (`src/effort.ts`, part `46-us-effort`): a screen before the year's first American briefing, 1942 to 1945, while the flag `usEffort_<year>` is unset (gated in 50-app by `effortYear`); `effortStage` runs after `strainStage` in the `stage` memo for `american` only, measured from `RECORD_ALLOCATION`, so the record's choice leaves the written odds alone. A rule change here belongs in `src/effort.ts` and `tests/effort.test.mjs`.

## Dispatches 1940's guide (still in force)

React 19 + Tone.js, esbuild + Tailwind v4. Four campaigns, 278 nodes, Easy / Standard / hard modes (Führer, Purge, Coalition, Axis), region map, wire bulletins, Historical Divergence forks, and the Key Battle (Order of Battle) subgame. Two build variants: `full` and `demo`. Assets: `assets/theme.mp3` (inlined into the bundle as a data URL), `assets/maps/` (region geometry JSON plus placeholder PNGs).

## Layout
- `src/App.jsx` (~23.6k lines, 1.9 MB): `CAMPAIGNS` (lines ~70-14000, node getters that read `flags`/`meters`), then maps, screens, the battle subgame, and `WW2CommandInner` (the run state machine near the end). **Never read it whole.** Grep and ranged Read only.
- `src/logic.ts` the pure run logic (typed; no React/DOM/storage/sound/`Math.random`): choice resolution (roll, battle nudge, plan costs, flags, hard-mode ceilings, meters), log entry, next position, divergence-fork arrival, Führer-mode necessity rule. App.jsx calls it. Content is passed in, never imported.
- `src/main.jsx`, `src/tailwind.css`, `build.mjs` build. `tools/` data audits (`npm run audit`), `tools/extract_campaigns.js` (loads CAMPAIGNS in Node), `tests/ui.config.mjs` (config for the shared headless driver in `../packages/testkit`). `tests/baseline/ui/` recorded runs from the pre-refactor build. `docs/` devlog, specs, reports.

## Editing surface: src/parts/ (not src/App.jsx)
`src/App.jsx` is an assembled artifact (the validators, extractors and baselines read it). Edit the parts in `src/parts/`: `00-head`, one file per campaign (`10-campaign-german`, `11-campaign-soviet`, `12-campaign-allied`, `13-campaign-italy`), `20-registries-and-gallery`, `25-battle-subgame`, `30-warroom-and-maps`, `40-select-briefing-end-screens`, `45-dossiers-objectives`, `50-app`. A session that touches one campaign needs that one part plus this file.
- `npm run build` assembles the parts into `src/App.jsx` first, and refuses if `src/App.jsx` is newer than every part (you edited the artifact by hand). Run `npm run split` to push such an edit back into the parts, or revert it.
- `npm run assemble` / `npm run roundtrip` (proves split then assemble is byte-identical) are available on their own. The split points live in `split.config.json`; the tool is `../packages/testkit/src/split.mjs`.
- Both the parts and the artifact are committed.

## Commands
- `npm run build:nozip` writes `dist/full` and `dist/demo`. `npm run build` also zips into `builds/` and needs the `zip` CLI (absent on stock Windows).
- `npm run audit` all data audits (reachability, advisor dates, pace text, outcome sign, battle balance, micro-state filing, quotations, map, claims). Run before and after content changes.
- `npm run typecheck` checks `src/logic.ts` (App.jsx is untyped).
- `npm run verify:baseline` plays 48 seeded runs (4 campaigns x easy/standard/hard x 4 seeds) headlessly in jsdom through `dist/full/bundle.js`, hashes the page after every click and compares with `tests/baseline/ui`. Roughly 4 minutes on Linux, 8 on Windows (every run loads the 7 MB bundle). Build first. Must report 0 failures.
- `TRACE=1 node ../packages/testkit/src/cli.mjs one <german|soviet|allied|italy>-<easy|open|hard> <seed>` prints one run step by step; `DUMP_STEP=<i>` prints the full page text after click i (diff two builds with `BUNDLE=<path>`).

- Advisers carry `position` (what the named person argued, in the third person), never invented speech. A real quotation goes in `attested: { by, text, source }` on the same choice (shown in speech marks instead of the position) and in `claims/quotations.json`; `npm run check-quotations` enforces it.
- `npm run test:battle-resume` plays to a battle, saves from the planning screen and the report, resumes in fresh pages and checks the screens come back identical (run after a build).

## Rules
- Each meter has micro-states (`METER_STRANDS` in `src/logic.ts`: Manpower Organisation/Experience/Readiness, Matériel Fuel & Oil/Arms & Ammunition/Shipping & Rail (three, like the others; `matAmmo` and `matSteel` in old saves still count toward Arms & Ammunition), Initiative Intelligence/Command/Tempo), filed by what the choice's text is about and tallied in flags (`man*`, `mat*`, `ini*`). A meter at -8 or below reads Exhausted. What a cost takes below -10 is owed (`arrears*` flags, cap 6) and gains pay it first. `strainStage` worsens the odds of contested choices when a meter is short, and the stage the player sees is the stage that is rolled. A new tally or arrears flag must be added to `TALLY_FLAGS` in `packages/engine/tests/campaign-equivalence.test.mjs`.
- A battle's plan charges are held to one point on a meter its outcome already cost two or more (`resolveChoice`); `computeBattlePlanCosts` no longer charges an uncovered arm on a loss.
- The checkpoint map's baseline is the dated `MAP_TIMELINE` (36 regions, nine of them the Eastern Front zones that `tools/split-ussr-zones.mjs` cuts out of the three the Python pipeline writes) in `30-warroom-and-maps.jsx`, read at the node's own date (`nodeDayKey`, `baselineStatuses`); run-specific changes are `mapOverrides(year, flags, meters, dayKey)` in `40-...`. `npm run check-map` keeps the timeline in step with `MAP_YEAR_STATUS` and tests that decisions move the map. A decision that decides a country's fate needs an override, or the map will not show it.
- The main screen picks a command; `DifficultyScreen` picks the difficulty (`modeFeatures`, `warRoomModeInfo` in `25-...`). The battle report runs on its own once started (`BATTLE_BEAT_MS`), newest line first, and stops for decisions; with instant text, reduced motion or a staff plan it does not wait. `npm run test:logic` covers arrears, strain, the stack cap, the bands and the command rank.
- Game decisions go through `src/logic.ts`, not inline in the component.
- `modWeight` and the other helpers CAMPAIGNS calls stay defined in App.jsx above the screens; `tools/extract_campaigns.js` transpiles the whole file with stubs. Imports in App.jsx must stay single-line (the extractor strips single-line imports only), and any new asset import needs a stub in the extractor's prelude (the music data URL and map JSON are stubbed there).
- `Math.random` call sites: the roll in `chooseOption`, `rollDivergenceForks`, battle simulation. Call order is part of the recorded behaviour.
- A deliberate behaviour change means re-recording the baseline (rebuild the old version from git history, record, then record the new one) and saying so.
- Legacy build for comparisons: `src/App.jsx` at the import commit (`git log -- "Dispatches 1940/src/App.jsx"`), built with this folder's `build.mjs`.

## Known legacy behaviour
- FIXED: the outcome screen and `proceed()` looked up the player's choice in a stage re-resolved AFTER the choice applied its impact. When that changes the choice list (a meter-gated choice appears or disappears), the index points at a different choice: the game showed another choice's outcome text and routed by it. Seen: `allied-hard-2` clicked "Press Stalin hard on free Polish elections" and was shown the outcome of "Accept the ambiguous language". The same defect crashed the shipped 1941 when the index fell off the end of the list. `proceed()` now always reads a snapshot of the stage the player faced (`outcomeStage`/`seenStage`), and the outcome screen uses the live stage as before unless it no longer holds the picked choice (`displayStage`).
- FIXED (decided 2026-10): the after-action log is built from that snapshot, so the end screen's "compound likelihood" odds and the log-derived figures are what the player actually faced (legacy computed them from the stage re-resolved after the choice moved the meters). Roll-odds reveals shown on the outcome screen itself are unchanged.
- Baseline was re-recorded once for these two changes. Evidence: with percentages and parenthesised counts masked, 43 of 48 legacy runs are identical to the new build; the other 5 are the one wrong-choice run (`allied-hard-2`, from step 85) and 3 German runs whose only difference is a decimal odds figure the mask missed (~6.7% vs ~5.8%). `tests/baseline/ui` is now the new build's behaviour.
- The 1940 `logic.ts` calls the engine's campaign primitives (`packages/engine/src/campaign.ts`); `packages/engine/tests/campaign-equivalence.test.mjs` proves they match this game's own rules.
- FIXED (tooling): `tools/extract_campaigns.js` had stopped working (`THEME_MUSIC_DATA_URL is not defined`) once the music import was added, so the audits that need it could not run. Stubbed in the extractor. All five audits give identical output on the old and new source.
- FIXED (tooling): `build.mjs` ran the Tailwind `.bin` shim (fails on Windows) and required the `zip` CLI; it now runs Tailwind through node and accepts `--no-zip`.
- The shipped `builds/*.zip` are older than this source and not reproducible byte-for-byte.

## Changing behaviour (details: ../docs/WORKFLOW.md)
- After any change run `npm run test:fast`. When `verify:baseline` fails: if it is a bug you introduced, fix the code; if the change is intended, read the reported differences, run `npm run baseline:accept`, and commit the new baseline together with the change and a line in `CHANGELOG.md`. A fix of a legacy bug that the old build got wrong goes in `tests/baseline/known-diffs.json` instead (first differing step plus a one-line reason).
- Saves: the run and war record are written to `ww2-command-active` / `ww2-command-record` through `window.storage`, which `src/parts/00-head.jsx` defines on top of localStorage (it only exists natively in Claude's artifact environment; before this was added, nothing saved on itch.io or Windows). `SAVE_VERSION`, `NODE_ALIASES`, `SAVE_MIGRATIONS` and `migrateSave` follow docs/SAVES.md; `npm run test:saves` and `npm run test:migration` guard them.
- Real-browser check (from the repo root, after building): `npm run smoke:browser`. Known layout findings are listed in `tests/browser-allowlist.json`.

Writing: follow `../docs/WRITING.md`. `npm run check-writing` fails on an em dash in on-screen text.

## Trust, special dispatches, orders on the map, balance and the playthrough bot
- **Trust** is rule code in `src/logic.ts` (`trustAfter`, called by `resolveChoice`; `adviserStanding`, `trustedAdvisers`) kept in the flags `tr_<name>` (half-points, -6 to +6), `trn_<name>` (the display name) and `trgone_<name>`. The card line is `AdviserLine` in `40-...`; the free reconnaissance pass is in `BattleAllocationScreen`. Any new flag family has to be stripped in the root `packages/engine/tests/campaign-equivalence.test.mjs` (`withoutTallies`), or CI fails.
- **Special dispatches**: data `SPECIAL_EVENTS` and `SpecialEventScreen` in `src/parts/35-events.jsx`; `dueEvent` in `src/logic.ts` decides; `proceed()` in `50-app.jsx` shows the event first and the wire bulletin after it, and marks `ev_<id>` at once. An event is tied to reports by id (`at`), never by date: node dates are free text. `npm run check-events`.
- **Orders on the map**: `MAP_OPS[campaign][nodeId]` in `src/parts/36-map-ops.jsx`, each order found by the start of its label (`match`, which must keep the label's own spelling); `CheckpointMap` takes `orders`, `MapOpArrows` draws. A report drawn has all its orders drawn. `npm run check-map-ops`.
- **The front, the places and the ground on the map**: `src/parts/37-map-front.jsx` holds `FRONT_SERIES` (dated lines by theatre; `frontsOn` draws a theatre only where its watched regions stand as the record had them or are still contested, dashed red if the run has departed from the record), `MAP_PLACES` (every report has a [lon, lat]; a new report needs one), `MAP_MEANWHILE` (what each command did in the record, for the pins) and `MAP_GROUND` (a flag and values that mark a place held or lost against the record; the flag must be set by some order). `npm run check-map-front` checks all four.
- **The map under the report and the conditions**: `ReportMap` (in `src/parts/37-map-front.jsx`) is mounted under the title by the briefing screen and opens `CheckpointMap` from its button; `src/parts/38-conditions.jsx` holds `COMMS` (hours of news by command and year, modelled), the climates by place (read from `MAP_PLACES`), `railReading` and `BOMBARDMENTS` (sourced). `npm run check-conditions`.
- **The sketch of the ground**: `src/parts/39-battle-sketch.jsx` (`BattleSketch`, `battleArmStatuses`) is mounted by the Order of Battle planning screen (counters) and the battle report (the line by arm) in `40-select-briefing-end-screens.jsx`. Its statuses are read off `computeBattleContributions`, never rolled. `npm run check-battle-sketch`.
- **Reading aids and the share card**: `ReadAloud` and `DYSLEXIA_CSS` are at the end of `src/parts/38-conditions.jsx` (the typeface setting is kept in `dispatches1940_dyslexia`); `src/parts/41-share-card.jsx` draws the card as an SVG (system fonts only) and `ShareCardButton` makes a PNG of it for the ending screen. `npm run check-share-card`.
- **Interface text goes through `t()`**: write every new button, label or sentence of the interface as `t("English")` (with placeholders, never joined pieces), or `T("English")` in a data table and `t(value)` where it is shown; then add the six translations in `src/i18n/*.json` (`node tools/i18n.mjs --sync`). `npm run check-i18n` is in `test:fast`. Reports, advisers' words and map notes stay English. See `docs/LOCALISATION.md`.
- **The staff's reading**: `src/parts/42-staffs-reading.jsx` holds `INTEL_ITEMS` (by command and report; `relied` is the positions of the orders that rest on the belief), the checks (`ix_<node>_<id>` and `ix_used` in the flags) and `IntelPanel`; `40` mounts the panel under the report and the line under each order; the button begins with Show so that the UI bot never presses it. Nothing in the rules reads it. `npm run check-staffs-reading`.
- **The look of the maps**: `MapFrontLines` (with `frontTeeth`), `MapFrontMarks` and `ReportMap` (with `mapScaleBar`, `MapGrain` and the key) are in `src/parts/37-map-front.jsx`; the names, seas, towns and the muted fills are in `CheckpointMapRegions` in `30`, which takes `zoom` and `clip` so that marks keep their size and cut labels are dropped. The colours are `STATUS_COLORS` in `40`. A new mark must scale by `1 / zoom`, and a map wrapper needs the class `dg-reportmap` (and `dg-reportmap-inner` for what is drawn) so that Night reading can turn it to a dark chart.
- **Balance**: `npm run balance` (`tools/balance.mjs`, `docs/BALANCE.md`). Change a campaign's costs, then read the pinned-meter line and `npm run check-endings`; do not tune by feel.
- **Playthrough**: `npm run playthrough` (needs `npm run build:nozip` and Playwright's Chromium) plays all four campaigns in a real browser; 1940 has no screen markers, so it reads button text like `tests/ui.config.mjs`. In CI's `browser` job.
- The new text is written in British English (the game as a whole is mixed); `match` strings copy the game's label exactly.
